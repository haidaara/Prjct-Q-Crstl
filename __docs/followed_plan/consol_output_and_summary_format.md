## **3. LOG FILTERING RULES (Verbosity 2)**

Not EVERY flip is logged. Filters based on:

### **Always Log (Verbosity 2):**
- Stage start/end
- Snapshot creation
- Errors/warnings
- Defect creation attempts (successful only)
- Energy checks (if drift > threshold)
- Large energy changes (>0.5 ΔE)

### **Filtered Out (Too Noisy):**
- Rejected flips with small ΔE
- Normal MC steps (unless interesting)
- Periodic energy checks with no drift
- Minor metric updates

### **Sampled Logging:**
- Flip acceptance every 100 steps (summary)
- Energy total every 500 steps
- Defect count every 1000 steps

## **2. CLARIFICATION: METRICS FILES**

You asked what metrics are. Let me clarify:

**Metrics are quantitative measurements of your simulation:**

1. **Time-Series Metrics** (`metrics/checkpoints.jsonl`):
   ```json
   {"step": 0, "time": 0.0, "energy_total": 1569.05, "defect_count": 15, "temperature": 5.0}
   {"step": 100, "time": 10.2, "energy_total": 1545.32, "defect_count": 12, "temperature": 5.0}
   {"step": 200, "time": 20.5, "energy_total": 1532.15, "defect_count": 9, "temperature": 5.0}
   ```

2. **Aggregated Metrics** (`metrics/aggregates.json`):
   ```json
   {
     "healing_efficiency": 0.8,
     "total_energy_change": -45.6,
     "final_defect_count": 3,
     "acceptance_rate_by_temperature": {
       "5.0": 0.15,
       "3.0": 0.12,
       "1.0": 0.08
     }
   }
   ```

3. **Spatial Metrics** (optional, `metrics/spatial.json`):
   ```json
   {
     "defects_near_obstacles": 5,
     "defects_far_from_obstacles": 2,
     "healing_efficiency_by_distance": {
       "0-2": 0.6,
       "2-5": 0.8,
       "5+": 0.9
     }
   }
   ```

**These metrics come from:**
- Your existing `MetricsTracker` in healing
- Energy model outputs (`vertex_class`, `energy_class` counts)
- Flip statistics from MC engine
