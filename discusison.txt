## 3) The real inconsistency (❌ important): `is_outer_edge` is never set correctly

In **both** new obstacle outputs, tiles have `is_outer_edge: false` even when they are clearly on the **outer boundary** (example from pores output) .

Why this matters:

* Your energy model explicitly uses `is_outer_edge` to decide whether a boundary tile is `"outer_edge"` or `"pore_edge"` .
* If `is_outer_edge` is always false, then **outer boundary tiles get mislabeled as `pore_edge`**, and you cannot reliably distinguish:

  * boundary-from-window vs boundary-from-pore

This matches what you’re seeing: boundary classification feels “not logical” even though the energies themselves are consistent.

### Where the bug comes from (in src)

* In `src/energy/widom_inspired_energy.py`, boundary kind selection depends on `tile.get("is_outer_edge", False)` .
* In `src/obstacle/obstacle_creator.py`, you preserve `neighbors_full` before pruning (good), but you **never compute `is_outer_edge`** .

## 4) Minimal fix (exactly what/where to change)

### File: `src/obstacle/obstacle_creator.py`

**Goal:** set `is_outer_edge` once, using the *truthful* pre-pruned neighbor list:

* A Penrose rhombus has 4 edges → an outer-boundary tile is exactly one with `len(neighbors_full) < 4`.

#### Find this block inside `_update_adjacency_batch`:

```python
tile.setdefault("neighbors_full", [int(n) for n in tile.get("neighbors", [])])
```

(it’s right here)

#### Replace it with:

```python
tile.setdefault("neighbors_full", [int(n) for n in tile.get("neighbors", [])])
tile["is_outer_edge"] = (len(tile["neighbors_full"]) < 4)
```

**Why this is the correct minimal fix**

* It uses *already-preserved* topology (`neighbors_full`) that includes neighbors before pore pruning .
* After this, `WidomInspiredEnergy` will correctly label:

  * outer boundary tiles as `"outer_edge"`
  * pore boundary tiles as `"pore_edge"`
* No physics is changed; it only fixes a classification field that your physics code already expects.
